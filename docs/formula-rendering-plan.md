# 飞书公式混合渲染实施计划

## 目标

在不降低现有 Codex 流式反馈、工具卡片、会话、附件、Provider 和并发能力的前提下，让飞书最终回复中的数学公式可读：

- 普通正文保持飞书原生 Markdown。
- 简单行内公式转换为可复制的 Unicode 文本。
- 独立复杂公式渲染为局部图片。
- 含复杂行内公式的正文段落整体排版为局部图片。
- 所有已渲染公式在卡片底部折叠保留 LaTeX 源码。

## 判定规则

Bridge 只分析明确的 LaTeX 定界符：`$...$`、`\(...\)`、`$$...$$` 和 `\[...\]`。代码围栏、价格、未闭合定界符不参与转换。

以下结构判定为复杂公式：分式、根式、求和/积分、矩阵、分段/对齐、运算符名称、嵌套上下标、较长表达式或无法安全转换的 LaTeX 命令。

- 简单行内公式：保留文字并转换常见希腊字母、运算符、上下标。
- 复杂行内公式：渲染它所在的一个段落。
- 块级公式：只渲染公式自身。
- 每条回复最多生成 8 张图，单段最多 1400 字符，整个公式后处理默认最多 15 秒。超长段落保留原文，不生成超高图片。

## 运行时与降级

1. Codex 与 CardKit 仍按现有路径并行启动。
2. 运行中的卡片继续显示原始流式文字。
3. Codex 完成后才进行公式分析、KaTeX 排版、图片上传和最终卡片替换。
4. 浏览器缺失、KaTeX 错误、截图失败、网络超时或飞书上传失败时，保留原始 Markdown。
5. 临时 PNG 在上传后立即删除，浏览器在本轮结束后关闭。

## 验收

- 纯文本回复没有浏览器启动成本。
- 代码与货币文本不被误判。
- 简单公式保持可复制。
- 复杂行内公式段落和块级公式均可生成清晰 PNG。
- 飞书图片上传使用 stdin JSON 和相对文件参数。
- 完整测试、真实浏览器烟雾测试、桌面打包和已安装客户端验证通过。
- 当前 Windows、旧 Windows、`origin/main`、GitHub Release 和已安装客户端版本一致。
