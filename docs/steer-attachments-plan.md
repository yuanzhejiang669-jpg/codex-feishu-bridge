# `/steer` 附件支持规划

状态：实施中  
目标版本：Desktop `0.8.3`  
日期：2026-07-27

## 目标

在不改变普通消息队列、其他斜杠命令和现有 Codex 会话模型的前提下，让飞书中的 `/steer` 能把文字、图片和普通文件追加到当前正在运行的原生 Codex turn。

## 范围

1. `/steer` 在进入命令处理前下载同一条飞书消息携带的图片和文件。
2. 合并此前单独发送并暂存的附件。
3. 图片作为原生 `localImage` 输入；普通文件沿用本地路径上下文。
4. 多次 `/steer` 继续通过现有 `steerInFlight` 串行进入同一个 turn。
5. 下载失败、turn 未就绪或 steer 竞争失败时不得误报成功；已下载附件应保留供重试。
6. 成功回执显示实际追加的图片和文件数量。

## 非目标

- 不新增其他 Codex 斜杠命令。
- 不改变 `/stop`、`/status` 等旁路命令的快速处理路径。
- 不改变普通消息附件的下载和任务创建方式。
- 不把一个已结束的 turn 自动替换成新任务。

## 验证

1. 源码语法、根项目全套测试和 Desktop 全套测试。
2. 原生 Codex app-server `turn/steer + localImage` 实测。
3. 打包 Engine 一致性与 Windows Release 校验。
4. 对抗性审查：
   - 普通命令入口与旁路命令入口出现行为漂移；
   - 下载或 turn 生命周期竞争导致附件静默丢失；
   - 快速连续 steer 导致顺序错乱或重复附件。
5. 发布后核对当前设备、旧 Windows、GitHub Release 和 Bot 在线状态。

## 发布边界

- 只重启 `active-runs.json` 中无活动 run 的 Bot。
- 当前承载发布会话的 Bot 不被中断，使用已有空闲后延迟升级机制。
- 旧设备只允许快进更新，并保留其无关未提交改动。
