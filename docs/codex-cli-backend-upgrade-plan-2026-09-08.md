# Codex CLI 优先后端：实施规划

## 目标与范围

在当前 Windows、旧 Windows、Mac、Ubuntu 使用完整安装的官方 Codex CLI，保留 App Server 协议、已有会话、Provider、配置空间和 Bot 身份。系统页区分检测到的后端与实际运行后端。发布正式客户端，安装和启动效果应与用户手动升级并打开客户端一致。

## 策略

1. 明确配置的后端优先；自动发现优先经过验证的官方 CLI；桌面包提取作为备用。
2. 保留官方 CLI 安装目录结构，不将 npm/独立包扁平复制为几个 EXE。
3. 不凭 PATH 或版本号单独判断可用性：验证可执行、App Server 握手与最小任务；记录选择原因及实际路径。
4. 安装新版不等于运行新版。Bot 空闲后重启并重新发现后端，记录实际启动版本；不终止活动任务。
5. Mac 优先直连安装源，不通则传输经校验的匹配架构官方包；不修改系统代理或学校 VPN。
6. 不重写飞书协议，不改变模型、Provider、权限、Skills/MCP 或用户数据。

## 验收与停止条件

全部必需设备/发布/客户端均核验才报告完成。活动中的当前 Bot 安排任务后空闲重启；未核验部分明确标记。未知用户改动不打包提交；若不能安全隔离则停止发布并说明。网络、权限、设备离线须提供实际错误，不假称成功。
